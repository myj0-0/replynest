# 架构与边界

ReplyNest 的托管服务入口为 [replynest.cn](https://replynest.cn/)。开源部署使用自己的域名与数据，不连接官方租户。

```text
网站访客 / 微信用户
       │
渠道接入与鉴权 → TypeScript Gateway → PostgreSQL / Redis
       │                 │
       │          Policy / RAG / AI / 自动化任务
       │                 │
  Chatwoot CE ← 最小内部 Overlay
       │                 │
  人工会话底座       Console / 自研客服工作台
                         │
                  已授权的外部通知与业务接口
```

- **Console**：Next.js 服务端会话与同源 API 代理，包含租户功能、工作台、公开官网、合成演示和内部管理界面。
- **Gateway**：租户鉴权、渠道收发、成员、客户、知识、账务、通知、自动化与用途授权。不能信任浏览器提交的租户／价格／权限。
- **Chatwoot CE Overlay**：身份、成员、会话和原生数据读写的最小受控桥接；保留原有会话与权限校验，不分发 Enterprise 目录。
- **Knowledge Worker**：隔离存储、安全扫描、受限解析、文档版本、分块／索引及任务恢复。
- **PostgreSQL／Redis**：持久化业务、向量检索、会话映射、幂等、队列及限流。生产的业务数据库与原生会话数据库应使用独立角色。
- **Code Runner**：工作流代码执行需认证、隔离和资源限制；提供源码不等于默认开启任意代码执行。
- **Help Docs／Monitor**：静态中英文教程与独立监控，不能因监控权限而取得租户聊天或模型密钥。

## 关键约束

所有查询／修改都必须保持租户边界。API 幂等键、Webhook 签名／重放窗口、任务去重、AI 预占／实际扣费和未知结果不盲目重试的策略不可删除。对外发送与真实执行需要渠道资格、角色和单独授权；预览不是执行。

知识来源必须同时符合当前发布版本、有效期、适用范围及人工确认要求。历史聊天只能在用途授权后用于对应任务，不自动成为企业政策。AI 备注不覆盖人工备注，图表汇总既有结果不再次调用模型。

本地初始化可使用 `legacy` 模式。生产应先由独立所有者完成迁移与权限配置，再使用只读结构校验的 `verify` 启动模式；不能仅切换一个变量就假设数据库已完成降权。
